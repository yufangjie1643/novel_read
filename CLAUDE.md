## Project Overview

Legado (开源阅读) is a free, open-source Android novel reader app. The core architecture is an Android Kotlin app with an embedded Vue 3 web UI module. Its distinguishing feature is a declarative rule engine that allows users to define custom web-scraping "book sources" for fetching novel content from arbitrary websites.

- **Repository**: https://github.com/gedoor/legado
- **Primary language**: Kotlin (Android)
- **Web module**: Vue 3 + Vite + Element Plus (`modules/web/`)
- **JDK**: 17 required
- **Min SDK**: 21, **Target/Compile SDK**: 36

## Build Commands

### Android App

All Gradle commands use the wrapper (`./gradlew` on Unix, `gradlew.bat` on Windows):

```bash
# Build debug APK
./gradlew assembleAppDebug

# Build release APK (requires signing config or will use debug signing)
./gradlew assembleAppRelease

# Build both release variants (release + releaseA/coexisting)
./gradlew assembleAppRelease
./gradlew assembleAppReleaseA

# Clean build
./gradlew clean

# Lint
./gradlew lint
```

Release builds have `minifyEnabled=true` and `shrinkResources=true` with ProGuard rules in `app/proguard-rules.pro` and `app/cronet-proguard-rules.pro`. The `releaseA` variant is a coexisting package (different applicationId suffix) that can be installed alongside the regular release build.

### Web Module (`modules/web/`)

The web module builds into `app/src/main/assets/web/vue/` which is served by the app's embedded NanoHTTPD server:

```bash
cd modules/web
pnpm i          # Install dependencies (requires Node >=20, pnpm >=9)
pnpm dev        # Development server (Vite)
pnpm build      # Production build + sync to app assets
pnpm build-only # Build without type-check
pnpm type-check # Vue TypeScript check
pnpm lint:fix   # ESLint --fix
pnpm format     # Prettier formatting
```

Do not manually edit files under `app/src/main/assets/web/vue/` — they are auto-generated by the web build.

### Cronet Download

Cronet (Chromium networking) JARs and SO files are downloaded from Google Storage. Version is set in `gradle.properties` (`CronetVersion`, `CronetMainVersion`):

```bash
# Update Cronet after changing version in gradle.properties
./gradlew app:downloadCronet
```

## Architecture

### UI Layer

- **Base classes**: `BaseActivity<VB>` / `VMBaseActivity<VB, VM>` and `BaseFragment` / `VMBaseFragment<VM>` provide ViewBinding, theming, and ViewModel wiring.
- **Adapter base**: `RecyclerAdapter<ITEM, VB>` is the generic RecyclerView adapter with headers/footers, DiffUtil integration, and item animations.
- **ViewModels**: `BaseViewModel` provides `execute()` / `executeLazy()` / `submit()` methods that wrap coroutines in a custom `Coroutine<T>` chainable wrapper (RxJava-like `onSuccess`/`onError`/`onFinally` over coroutines).

### Data Layer

- **No explicit Repository layer** — ViewModels and business-logic singletons access DAOs directly via the global `appDb` lazy singleton (`AppDatabase.kt`).
- **Room database** with 20+ entities (`Book`, `BookSource`, `BookChapter`, `RssSource`, `RssArticle`, `ReplaceRule`, etc.). Schema version is 75. Schema exports are in `app/schemas/`.
- **KSP** is used for Room and Glide code generation (not kapt).
- Entities use `@TypeConverters` for JSON-serialized nested objects and implement `Parcelable` for inter-component passing.

### Business Logic

Heavy use of Kotlin `object` singletons for core logic rather than dependency injection:

| Singleton | Responsibility |
|-----------|---------------|
| `WebBook` | Orchestrates web scraping: search, explore, book info, TOC, content fetching |
| `ReadBook` | Reading session manager (lives in `MainScope`) |
| `CacheBook` | Chapter pre-download queue manager |
| `BookHelp` | File cache operations, chapter matching, cover handling |
| `LocalBook` | Local file import (TXT, EPUB, PDF, UMD, MOBI) |

### Book Source Rule Engine

The app's core differentiator. Users define `BookSource` entities with rule strings that the engine evaluates at runtime:

- **`AnalyzeRule`** (`model/analyzeRule/AnalyzeRule.kt`) — Central rule evaluator. Parses rule strings and dispatches to the appropriate analyzer.
- **`AnalyzeUrl`** (`model/analyzeRule/AnalyzeUrl.kt`) — URL construction with JS interpolation, page params, POST body, headers, and WebView fallback.
- **Analyzers**: `AnalyzeByJSoup` (CSS selectors), `AnalyzeByXPath` (XPath), `AnalyzeByJSonPath` (JSONPath), `AnalyzeByRegex` (regex extraction).
- **`RuleAnalyzer`** — Parses rule strings with `{{js}}` interpolation.

Rule syntax prefixes (auto-detected):
- `@XPath:` — XPath mode
- `@Json:` / `$.` — JSONPath mode
- `@CSS:` / `@@` — CSS/JSoup mode
- `{{js}}` — Inline JavaScript
- `@js:` / `<js></js>` — JavaScript blocks
- `##match##replace` — Regex replacement

JavaScript execution:
- **Mozilla Rhino** (`modules:rhino`) provides the JS engine.
- `RhinoScriptEngine` executes JS rules.
- `JsExtensions` interface provides 100+ utility functions callable from JS (ajax, file ops, encoding, fonts, zip, etc.).
- `NativeBaseSource` factory wraps source entities for JS access.

### Services

Multiple foreground services handle background work (all extend `BaseService` which extends `LifecycleService`):

- `WebService` — Embedded HTTP + WebSocket server
- `BaseReadAloudService` / `TTSReadAloudService` / `HttpReadAloudService` — TTS/read-aloud with media session
- `AudioPlayService` — Audio file playback
- `CacheBookService` — Background chapter pre-downloading
- `DownloadService` — Book export/download
- `CheckSourceService` — Book source validation
- `ExportBookService` — Book content export

### Web Server

- **HTTP**: `HttpServer.kt` (NanoHTTPD) serves static assets from `assets/web/` and REST API endpoints.
- **WebSocket**: `WebSocketServer.kt` (NanoWSD) provides real-time source debugging at `/bookSourceDebug`, `/rssSourceDebug`, `/searchBook`.
- **Controllers**: `BookController`, `BookSourceController`, `RssSourceController`, `ReplaceRuleController` in `app/src/main/java/io/legado/app/api/controller/`.
- **Content Provider**: `ReaderProvider.kt` exposes a `content://` API for external apps.

## Dependency Management

Dependencies are centralized in `gradle/libs.versions.toml`. Key pinned versions (do not upgrade without verifying compatibility):

- **jsoup** `1.16.2` — Pinned due to a breaking change in newer versions affecting `AnalyzeByJSoup.kt` and JsoupXpath (see issue #3811).
- **commons-text** `1.13.1` — Pinned; newer versions use `Arrays.setAll` missing on Android < 6.
- **rhino** `1.8.1` — Pinned; newer versions use `VarHandle.compareAndExchange` unavailable on Android < 8.
- **media3** `1.8.0`, **room** `2.7.1`, **lifecycle** `2.9.4` — Pinned for compatibility.
- **hutool** `5.8.22` — Pinned; marked "do not update version".

## CI / Automation

GitHub Actions workflows are in `.github/workflows/`:

- `test.yml` — Builds `release` and `releaseA` APKs on push/PR, creates beta pre-releases
- `web.yml` — Builds web module and auto-commits output to `app/src/main/assets/web/vue/`
- `release.yml` — Official release builds + Google Play upload
- `cronet.yml` — Cronet version updates

The test workflow uses JDK 17 (Temurin) and injects a debug signing config automatically.
